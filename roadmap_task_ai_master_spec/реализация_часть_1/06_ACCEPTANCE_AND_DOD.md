# Acceptance Criteria and Definition of Done

## Цель
Унифицировать понимание того, когда задача, фича или этап считаются завершенными.

---

# 1. Definition of Done для задачи
Задача считается завершенной, если:
- есть понятный результат;
- он соответствует scope;
- есть код/схема/документ;
- есть self-check;
- обновлен прогресс-трекер;
- описаны ограничения и следующий шаг.

---

# 2. Definition of Done для фичи
Фича считается завершенной, если:
- реализованы все обязательные части;
- покрыты acceptance criteria;
- описаны API contracts;
- учтены ошибки и edge cases;
- понятно, как фича связана с другими модулями.

---

# 3. Definition of Done для этапа
Этап считается завершенным, если:
- закрыты все обязательные deliverables этапа;
- проставлены статусы в progress tracker;
- нет критических blockers;
- есть список перехода на следующий этап;
- зафиксированы архитектурные решения.

---

# 4. Формат acceptance criteria
Критерии должны быть:
- проверяемыми;
- конкретными;
- без двусмысленности;
- привязанными к поведению системы.

Пример:
Плохо:
- система работает быстро

Хорошо:
- список товаров для store context возвращается без данных других tenants
- заказ из POS можно создать и перевести в kitchen status flow

---

# 5. Чеклист завершения итерации
- [ ] Прочитан master spec
- [ ] Прочитан текущий phase doc
- [ ] Прочитан progress tracker
- [ ] Определен следующий подэтап
- [ ] Реализован deliverable
- [ ] Проверены acceptance criteria
- [ ] Обновлен progress tracker
- [ ] Зафиксированы решения / риски / техдолг
