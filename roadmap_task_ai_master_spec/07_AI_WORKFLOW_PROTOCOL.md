# AI Workflow Protocol

## Цель
Дать ИИ строгий рабочий протокол, чтобы он не терял контекст и не прыгал между задачами.

---

# 1. Что ИИ должен делать в начале каждой сессии
1. Прочитать master spec
2. Прочитать phase breakdown
3. Прочитать progress tracker
4. Определить активный этап
5. Определить незавершенные задачи
6. Выбрать следующую минимальную логичную задачу

---

# 2. Формат ответа ИИ в рабочей сессии

## Секция 1 — Context Check
- текущий этап
- что уже сделано
- что осталось

## Секция 2 — Next Step
- какая следующая задача
- почему именно она

## Секция 3 — Plan
- шаги реализации

## Секция 4 — Deliverable
- что будет создано

## Секция 5 — Acceptance Check
- как понять, что задача завершена

## Секция 6 — Status Update
- что нужно обновить в progress tracker

---

# 3. Что ИИ не должен делать
- не перепрыгивать через этапы без причины;
- не менять архитектурные решения без фиксации ADR;
- не пытаться реализовать весь проект одним куском;
- не создавать client-specific hacks в core;
- не считать задачу завершенной без acceptance check.

---

# 4. Как ИИ должен отмечать прогресс
После каждого завершенного куска работы ИИ должен:
- перенести задачу в Done;
- обновить Current Phase;
- отметить Next;
- записать новые решения;
- записать техдолг и ограничения.

---

# 5. Когда переходить к следующему этапу
Только если:
- закрыты обязательные deliverables текущего этапа;
- нет критических blockers;
- есть краткое summary по результатам этапа;
- обновлен progress tracker.
