# AI Implementation Pack
## Как использовать этот пакет документов для реализации проекта с помощью ИИ

## Текущий статус репозитория
- PHASE 0: completed
- PHASE 1: completed, live Postgres verification пройден
- PHASE 2: completed, catalog/pricing foundation реализован
- Следующая очередь: PHASE 3 planning

Этот пакет предназначен для того, чтобы ИИ:
- опирался на единое ТЗ;
- видел текущий этап разработки;
- понимал, что уже завершено;
- фиксировал результаты каждого шага;
- не терял контекст между сессиями;
- работал итеративно и проверяемо.

# 1. Рекомендуемый принцип работы с ИИ

## 1.1 Не просить ИИ “сделай весь проект сразу”
Лучше работать так:
1. выбрать один этап;
2. дать ИИ только нужные документы;
3. попросить сначала составить план реализации;
4. затем реализовать этап по подэтапам;
5. после каждого подэтапа обновлять статус;
6. только потом переходить дальше.

## 1.2 Что давать ИИ в каждом запросе
В каждый рабочий запрос лучше включать:
- основное ТЗ;
- файл этапа;
- файл статуса проекта;
- файл текущего sprint / task list;
- явную инструкцию: сначала анализ, затем план, затем реализация.

## 1.3 Какой режим работы самый эффективный
Лучший режим:
- один документ = одна зона ответственности;
- один этап = один deliverable;
- один запрос = одна завершенная задача или маленький набор связанных задач.

# 3. Как именно использовать документы

## Для старта
1. Открыть `01_MASTER_PROJECT_SPEC.md`
2. Открыть `03_PHASE_BREAKDOWN.md`
3. Создать копию `04_PROGRESS_TRACKER.md`
4. Создать копию `05_TASK_BOARD_TEMPLATE.md` для текущего этапа
5. Передать ИИ эти документы в одной сессии

## Для каждой новой итерации
Просить ИИ:
1. свериться с текущим статусом;
2. перечислить незавершенные задачи этапа;
3. выбрать ближайшую логичную подзадачу;
4. выполнить ее;
5. обновить секции:
   - Done
   - In Progress
   - Blocked
   - Next

# 4. Лучшая практика

## Делить проект на 3 уровня
### Уровень 1 — Master spec
Что строим вообще.

### Уровень 2 — Phase docs
Что строим на конкретном этапе.

### Уровень 3 — Sprint/task docs
Что ИИ должен сделать прямо сейчас.

Так ИИ не расплывается по всему проекту и не пытается “угадать” приоритеты.

---

# 5. Важный принцип

ИИ лучше работает, когда у него есть:
- четкие границы этапа;
- критерии приемки;
- чек-листы;
- формат обновления статуса.

Поэтому весь пакет ниже заточен именно под это.
